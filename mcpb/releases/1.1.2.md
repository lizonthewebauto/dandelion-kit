# Kit 1.1.2 release checks

This patch adds optional ready-install and first-finished-output counts. It changes JavaScript, the tool list and setup copy. Runtime dependencies do not change. Counts stay off until the person agrees. Owner and QA checks use `DANDELION_KIT_TELEMETRY=0`.

The desktop bundles use the owned 1.1.1 release as their native base. For each of Windows x64, Apple silicon Mac and Intel Mac:

1. Check the downloaded 1.1.1 archive against GitHub's published asset SHA-256.
2. Compare the full pinned dependency graph with the 1.1.1 source tag, ignoring only the root package version. Check each installed package's version, integrity, source and dependency/platform fields against that lock.
3. Keep every native dependency, asset and core font unchanged. Replace only `bin`, `core`, `server`, package metadata and setup/license documents from the new source. Set the manifest version and exact platform.
4. Validate the manifest and pack with the official `@anthropic-ai/mcpb` 2.1.2 CLI.
5. Check ZIP CRC, reject duplicate paths, compare every packaged source file with the new source tree, and compare every protected native/asset byte with the old archive.

[1.1.2.json](1.1.2.json) records the old and new asset digests and file counts. All three bundles pass those checks. The Windows bundle starts with 29 tools and makes a real image with reporting forced off. Native macOS checks were not rerun; the prior native dependency bytes and existing platform limits are retained. Do not describe this as a fresh Mac runtime check.

Source/plugin installs read the new source. Older desktop installers keep their old code until the person updates. Download requests are counted at the owned download link; source clones and plugin downloads are not package downloads. An install means the MCP tools are ready or the CLI's runtime packages finished installing. First use means a finished image, carousel or final video, not a draft, status check or attempted edit. Only opted-in local installs can report these two events.

Offline first-use reports keep a pending boolean and retry when the Kit next starts while counts are on. Report dates are the server's receipt dates. No files, words, account details or client dates are sent. Preference and event state use separate local files so an event acknowledgement cannot undo a later opt-out.
